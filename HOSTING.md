# Устранение 500 и Out of memory на hoster.by (CloudLinux)

## 1. Узнать точную причину падения

После того как сайт отдал 500 и вы перезапустили приложение:

- В **cPanel → Файловый менеджер** откройте корень приложения (`root-main`).
- Найдите файл **`startup.log`** (появится после попытки запуска).
- Откройте его и посмотрите последние строки — там будет текст ошибки (например, отсутствует `.next`, нет модуля, OOM и т.д.). Эту информацию можно передать в поддержку или использовать для следующих шагов.

## 2. В чём может быть причина

- **Node.js 22** на shared-хостинге часто даёт `WebAssembly.instantiate(): Out of memory` при старте.
- Нехватка памяти (лимиты LVE), отсутствие папки `.next` или неполные `node_modules` тоже приводят к тому, что приложение не запускается и Nginx отдаёт **500**.

## 3. Что сделать по шагам

### A. Попробовать деплой через standalone (меньше памяти)

Соберите на своём ПК папку только для запуска (без полного репозитория и без сборки на сервере):

```bash
npm run build
npm run pack-deploy
```

Появится папка **`deploy`**. Залейте **всё её содержимое** в корень приложения на хостинге (`root-main`), чтобы в `root-main` лежали файлы `server.js`, `node_modules`, папки `.next` и `public`. В панели оставьте: корень приложения = `root-main`, файл запуска = **`server.js`**, затем перезапустите приложение. Так на сервере будет запускаться встроенный сервер Next.js из standalone, с минимальным набором модулей.

### B. Переключить приложение на Node.js 18

В панели hoster.by (Веб‑приложения → ваше приложение):

- Найдите **«Версия Node.js»**.
- Выберите **Node.js 18.x** (например 18.20 или 18.21), а не 22.
- Сохраните настройки и **перезапустите приложение**.

Node 18 на таких хостингах обычно стабильнее и реже уходит в OOM при старте.

### C. Задать переменную окружения (если панель даёт такую возможность)

Если в настройках приложения есть поля для переменных окружения, добавьте:

- Имя: `NODE_OPTIONS`  
- Значение: `--max-old-space-size=256`

Это ограничивает кучу Node и иногда помогает уложиться в лимиты. Сохраните и снова перезапустите приложение.

### D. Не собирать проект на хостинге

Сборку (`npm run build`) на сервере **не запускайте** — там мало памяти, сборка падает с OOM.

Делайте так:

1. **Локально** (у себя на ПК) в корне проекта выполните:
   ```bash
   npm run build
   ```
2. Убедитесь, что появилась папка **`.next`** (и при `output: "standalone"` — папка `.next/standalone`).
3. Залейте на хостинг в **корневой каталог приложения** (`root-main`):
   - весь проект, включая папку **`.next`**,
   - а также `server.js`, `package.json`, `node_modules` (или только то, что требует панель).

На сервере должны быть только:

- запуск приложения: **`npm start`** (т.е. `node server.js`) или только **`node server.js`**,
- при необходимости — **«Установить NPM пакеты»** (без `npm run build`).

### E. Проверить файл запуска

В настройках приложения в панели должно быть:

- **Файл запуска приложения:** `server.js`

Так и должно быть для cPanel/Passenger с нашим Custom Server.

### F. Если ошибка остаётся

- Напишите в поддержку hoster.by: попросите **увеличить лимиты LVE** (память/address space) для вашего аккаунта или для процессов Node.js, либо уточните, какие лимиты выделены.
- Альтернатива — перенос сайта на **VPS**, где лимиты памяти не так жёсткие и Node 22 обычно запускается без проблем.

---

**Кратко:** переключитесь на **Node 18** в панели, не запускайте `build` на хостинге (собирайте локально и загружайте `.next`), оставьте запуск через `server.js`. Если после этого 500 сохраняется — смотрите логи Passenger по Error ID и при необходимости обращайтесь в поддержку.
